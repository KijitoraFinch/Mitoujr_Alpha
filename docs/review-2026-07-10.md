# 実装レビュー（2026-07-10）

## 対象と結論

現在の作業ツリーにある Sugar、Bitter scaffold、JSON Schema、golden、検証 tool、
CI、設計文書を対象にしました。`PLAN_GLOBAL.md` は対象外です。

純粋な patch semantics、意味型からの正規化、strict decoder、scan/apply の実行可能な
slice は、参照実装の土台として妥当です。一方で、path を検査した後に path 文字列で
再度 filesystem operation を行うため、並行して directory topology を変更できる環境では
containment を証明できません。この問題を解決するまでは、filesystem slice を
production-safe と扱えません。

## 未解決の指摘

| 優先度 | 問題 | 影響 | 次の対応 |
| --- | --- | --- | --- |
| P0 | `Filesystem_apply` が component 検査後の read、temporary file、replace を path 文字列で行う | parent directory の差し替えにより workspace 外を参照する TOCTOU が残る | directory handle を保持し、POSIX は `openat`/`fstatat`/`renameat`、Windows は対応する handle API を使う |
| P0 | `Workspace_scan` も `lstat`、列挙、open を同一 handle に結び付けていない | symbolic link、FIFO、reparse point への差し替え、変更中 file の不安定な digest | apply と共有する handle-based read boundary と mutation detection を実装する |
| P0 | apply の directory flush failure を握り潰す | durability failure 後に `applied` を返し得る | 未対応 errno と実 failure を区別し、fault injection test を追加する |
| P1 | protocol integer の幅、schema-visible UTF-8、任意 byte replacement が未固定 | OCaml、Rust、JSON Schema、他言語 consumer の受理集合が一致しない | safe integer domain と text/byte variant を独立仕様にする |
| P1 | pure transition golden が実 `monika apply` を通らない | argument parser、JSON decoder、filesystem boundary、stdout の統合回帰を見逃す | temporary workspace を使う CLI end-to-end golden を追加する |
| P1 | 現行 `CommandResult` には inspect の region/annotation/reference collection がない | `inspect` の結果を version 2 で表現できない | CLI input、未解決 `RegionAddress`、scoped ID、正規形、次 schema version を実装前に固定する |
| P1 | `Annotation` が未解決 address を保持できず、共通 `Identifier.t` は ID kind と scope を区別しない | stale selector の明示情報喪失、複数 artifact の同名 ID 衝突 | `Region_address` と型付き・scoped ID を導入する |
| P2 | `Conflict.t` の公開 variant から不正 payload を直接構築できる | semantic model から schema 不適合値を生成できる | private representation と検証 constructor にする |
| P2 | macOS/Windows の必須 integration test がない | case folding、Unicode normalization、reparse point、replace semantics が未検証 | 3 platform の CI を release gate にする |
| P2 | opam の公開 metadata と license が未決定 | `opam lint` が maintainer 欠落を error とし、authors/homepage/bug-reports/license も警告する | package 公開前に所有者が authorship、連絡先、license を決定して `dune-project` へ記録する |
| P2 | filesystem failure summary が native absolute path と OS の error text を含む | 同じ失敗の JSON が platform や locale によって変わる | stable failure code と正規化した location を契約にし、native detail は非契約の debug 情報へ分ける |

具体的な実装順序と完了条件は [PLAN.md](../PLAN.md) にあります。

## 今回修正した事項

- scan root の symbolic link を一度だけ物理 path へ解決するようにしました。
- scan の read/列挙失敗を例外終了や warning success にせず、`internal-error` へ変換しました。
- scan の SHA-256 と byte size を 64 KiB chunk で計算し、artifact size に比例する memory
  使用を除去しました。
- 空の artifact `mediaType` を意味 constructor で拒否しました。
- workspace path の ordering を canonical string ordering に統一しました。
- filesystem entry policy と capability 不在を別 diagnostic code にしました。
- command-result schema に `status` と `exitClass`、code と default severity の関係を
  追加しました。
- required `artifacts` collection を追加した契約を schema version `"2"` とし、versioning
  policy を文書化しました。
- 未実装の region/reference/annotation/capability schema を fail closed にしました。
- standalone schema の外部 `$ref` を local registry で実際に解決して検証するようにしました。
- duplicate JSON key、非有限数、Python の bool/int/float 混同、object order drift、逆転
  range、transition 内の非 canonical path/content hex を検出するようにしました。
- fixture の workspace-relative path を `fixtures/basic` root と一致させました。
- Dune 生成 opam manifest を追跡対象にし、test dependency を `with-test` に分離し、
  `monika` executable を install target にしました。
- Bitter scaffold に format、clippy、test、stdout JSON smoke check を追加しました。
- 現行の制限と過去の設計検討を、権威のある設計・計画から区別しました。

## 2026-07-17 追補

P0 の filesystem 指摘のうち POSIX 境界を実装しました。`scan` と `apply` は共有 adapter
を通じて `openat`、`fstatat`、`renameat`、no-follow semantics を使用します。`apply` の
temporary file、mode、flush、置換、検証は保持中の parent descriptor に結び付きます。
directory flush は未対応 errno だけを許容し、その他の失敗を成功として扱いません。
`scan` は hash 前後の file state を比較し、1 回再試行しても安定しなければ失敗します。

Windows の retained-handle traversal、reparse-point rejection、handle-relative
temporary creation と replacement も実装しました。scan の mutation retry と、apply の
rename、directory flush、read-back の失敗は、それぞれ production と同じ有限状態の
処理へ決定的に注入しています。残る P0 の証拠は Windows/macOS の実機 CI です。
Wine headers による Windows C 分岐の compile は通していますが、実行時安全性の証拠には
数えません。したがって、filesystem release gate 全体はまだ完了していません。

仕様ゲートでは、JSON safe-integer と Unicode scalar UTF-8 の共有 corpus を追加し、Sugar、
specification validator、Bitter が同じ分類を行うようにしました。`Artifact_id` と
`Patch_id` は別の抽象型、`Conflict.t` は検証 constructor を持つ private variant です。
JSON Schema 外の意味制約は独立した `semantic_contract.py` に分離しました。artifact-local
な region/reference/annotation ID、未解決 `RegionAddress`、version 3 の observation
collections と厳密 schema を実装しました。apply の filesystem I/O failure は stable
code、operation、workspace-relative location を持つ正規形へ移行しました。
